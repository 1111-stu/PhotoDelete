# 相册页「个人收藏」入口：交互决策与 ASCII 原型

决策日期：2026-10-11。  
状态：**方案调整，Swift 已按标题栏入口实现（2026-10-11）；待真机回归。**
范围：相册页标题栏提供系统「个人收藏」快捷入口、进入现有浏览器/整理的闭环；不含首页专项清理改版、不含 App 内第二套收藏暂存区。

相关背景：

- 整理时点心形 = 立刻写系统 `PHAsset.isFavorite`（与系统「照片 → 个人收藏」同一标记），不是 App 暂存。
- 收集箱 / 本轮结算见 `organize-collection-bin-flow.md`。
- 相册排序与三种显示方式见 `style.md` §6.4、`albums-reorder-research.md`。

---

## 1. 一句话定稿

**个人收藏是系统智能相册；相册页标题栏将首页主卡片珊瑚色填充心形与「显示方式」并列；有内容时点进复用现有相册浏览器与整理，零收藏时显示空态；不进首页「专项清理」，不做 App 内收藏箱。**

---

## 2. 核心原则

| # | 原则 | 说明 |
| --- | --- | --- |
| P1 | 系统真相 | 读写都是系统 `isFavorite` / `smartAlbumFavorites`；App 不维护第二份收藏集合 |
| P2 | 快捷入口 | 相册页标题栏的个人收藏图标与显示方式入口并列，不占相册内容区 |
| P3 | 保留 ≠ 清理 | 不进首页「专项清理」（那是可删/可压对象）；收藏是保留信号 |
| P4 | 排序隔离 | 收藏入口只在标题栏；系统收藏不进入用户相册长按拖拽排序 |
| P5 | 复用路径 | 点进 → 现有 `AlbumBrowser` → 现有整理；不新做专用收藏页 |
| P6 | 空态可达 | 图标常驻；系统收藏数量为 0 时点按展示空态，不隐藏入口 |

---

## 3. 现状与缺口

| 层 | 现状 | 缺口 |
| --- | --- | --- |
| 写入 | 整理点心形 → `setPhotoFavoriteImmediately` → 系统收藏 | — |
| 数据 | `DataManager.systemAlbums` 已扫 `smartAlbumFavorites`；`photoLibraryManager.favorites` 有缓存 | — |
| 相册 UI | `AlbumsView` 标题栏提供首页主卡片珊瑚色填充心形；内容区只显示用户相册 | 入口不占内容区；零收藏也可发现和访问空态 |
| 首页 | 专项清理：相似 / 视频 / 截图 / 实况 / 录屏 | 无收藏入口（保持如此） |
| 旁路 | 相册浏览器内可筛「仅收藏」；最近整理可记 favorited | 标题栏入口负责「看全部个人收藏」 |

用户在整理里收藏后，App 内难以回看——本需求补的就是这条回路。

## 4. 交互决策表

| 入口 / 动作 | 行为 | 不做什么 |
| --- | --- | --- |
| 相册页标题栏心形 | 打开系统个人收藏的浏览器（与用户相册同一套） | 不直接全屏进整理（除非浏览器已有「开始整理」再进） |
| 收藏数量为 0 时点标题栏心形 | 显示「还没有收藏」轻量空态 sheet；入口保持常驻 | 不隐藏入口，不构造第二套收藏数据 |
| 浏览器内整理 | 队列 = 当前收藏集成员 | — |
| 整理中点心形（已收藏） | **取消收藏**（toggle）；可撤销 | 不是「再加入一次」 |
| 整理中上滑待删 | 进全局 `deleteCandidates` | **不**清系统收藏标记 |
| 从其他相册上滑待删 | 同上：只进收集箱 | **不**移出用户相册 / 智能相册 |
| 长按「我的相册」 | 照旧：整理 / 编辑 / 删除 + 拖排序 | — |
| 搜索 | 只匹配用户相册；标题栏收藏入口始终可见 | 搜索时仍禁用用户相册排序 |
| 数量 = 0 | 收藏图标仍可见；点击显示空态 | 不在内容区占卡位、不引导错误操作 |
| 首页专项清理 | — | **不加**「收藏」行 |

### 4.1 与待删除 / 收藏的交叉（已实现，文档固化）

| 场景 | 结果 |
| --- | --- |
| 已收藏 → 进收集箱 | 系统收藏**保留**；仅 App 暂存待删 |
| 待删除中 → 再点收藏 | 先移出收集箱，再标系统收藏（现有互斥） |
| 本轮结算「本次收藏」 | 只计净**新增**收藏（`favoriteActionCount`）；取消收藏不减成负数，下限 0 |
| 收集箱确认真删 | PhotoKit 删除后整库移除，收藏随之消失 |

## 5. ASCII 原型

### 5.1 相册页 · 标题栏双入口（有收藏）

```
┌──────────────────────────────────────┐
│  相册                     [♥] [▦]   │  ← 收藏（首页主卡片珊瑚色）与显示方式并列
│  N 个相册                             │
│  [🔍 搜索相册……………]          [＋]   │
│  我的相册                             │
│  ┌────────────┐  ┌────────────┐      │
│  │  封面 A    │  │  封面 B    │      │
│  │ 旅行 42    │  │ 家人 18    │      │
│  └────────────┘  └────────────┘      │
│  ┌────────────┐  ┌────────────┐      │
│  │  …         │  │  …         │      │
│  └────────────┘  └────────────┘      │
└──────────────────────────────────────┘
```

紧凑、封面、列表三种布局均使用同一组标题栏入口；收藏不占内容区，也不参与 reorder 槽位。

### 5.2 相册页 · 零收藏状态

```
┌──────────────────────────────────────┐
│  相册                     [♥] [▦]   │
│  N 个相册                             │
│  [🔍 搜索…]                   [＋]   │
│                                      │
│  点粉色心形                           │
│       ┌────────────────────┐         │
│       │         ♥          │         │
│       │    还没有收藏       │         │
│       │ 收藏的照片会显示在这里 │        │
│       └────────────────────┘         │
└──────────────────────────────────────┘
```

### 5.3 端到端路径

```
相册 Tab
  └─ 标题栏 [♥]
        ├─ count > 0 → 系统个人收藏相册
        │                 → AlbumBrowser（现有网格 / 筛选 / 整理入口）
        └─ count = 0 → 轻量空态 sheet
             → SwipePhotoView（队列 = 收藏集）
                  ├─ 心形 ──→ toggle 系统收藏（在此场景多为取消）
                  ├─ ↑ ──→ 全局收集箱（不清 isFavorite）
                  └─ ✓ ──→ 本轮结算（本次收藏 = 净新增，常为 0）
```

### 5.4 能力对照（个人收藏 vs 我的相册）

| 能力 | 标题栏收藏入口 | 我的相册 |
| --- | --- | --- |
| 点按 | 收藏浏览器；零张时空态 | 浏览器 |
| 浏览器 → 整理 | ✓ | ✓ |
| 长按菜单 | 不适用 | 整理 / 编辑 / 删除 |
| 拖拽排序 | 不适用 | ✓（搜索空时） |
| 新建 / 改名 / 删相册 | 不适用 | ✓（权限允许时） |

## 6. 文案

| 位置 | 文案 | 备注 |
| --- | --- | --- |
| 区标题 | 「系统」 | 便于日后扩展其他钉住的智能相册；若只永远一个钉，可改为「收藏」——实现前锁定为「系统」 |
| 行/卡标题 | 沿用 `L10n.favoritesCategoryTitle`（Favorites / 个人收藏等） | 跟系统本地化气质；不硬编码「收藏」 |
| 数量 | 无千分位整数 | 对齐 `style.md` |
| 副文案 | 列表页不强制写「来自系统照片」 | 避免噪音；进一次即懂 |

浏览器内已有「仅收藏」内容筛，**保留**（场景：在某个用户相册里看哪些打了心），与本入口不冲突。

## 7. 数据映射（实现对照）

| UI | Source of truth | 注意 |
| --- | --- | --- |
| 心形入口 | 固定显示；使用首页主卡片珊瑚色 `Theme.coralGradientTop`；VoiceOver 名称 Favorites | 勿绑定收藏数量显隐 |
| 点进 | `DataManager.favoritesAlbumForDisplay()` 非空时走 `AlbumNavigationDestination.browser` | 与用户相册同 destination |
| 空收藏 | 轻量空态 sheet；不创建假相册对象 | 照片收藏后自然转入浏览器路径 |
| 整理队列 | 相册成员或 `photoLibraryManager.favorites` | 取消收藏后会话刷新（现有 `onChange(favorites.count)` 已有） |
| 用户相册列表 | 只渲染 `getUserAlbums()` + 自定义排序 | **不要**把 favorites 塞进 `customAlbumOrder` |
| 旧 `favoriteCandidates` | 仅遗留迁移；整理写收藏已走 immediate | 本需求不复活暂存箱 UI |

## 8. 明确不做（本轮）

- 首页「专项清理」增加收藏行  
- 把个人收藏混入可排序用户相册网格或搜索结果
- App 内第二套「收藏收集箱 / 待确认收藏」  
- 系统智能相册入口一次上齐：最近项目 / 截图 / 视频 / 实况……（本轮只提供个人收藏快捷入口）
- 结算弹窗增加「本次取消收藏」  
- 为收藏单独做浏览器或整理 chrome

## 10. 决策日志（对话收敛）

1. 收藏写的是系统个人收藏，不是 App 暂存 → 展示应对齐系统相册心智。  
2. 主入口选相册页标题栏，与显示方式并列；用首页主卡片珊瑚色填充心形表达收藏，也释放相册内容区。
3. 不做 App 内收藏箱；进收集箱不清 `isFavorite`；进收集箱也不移出用户相册。  
4. 整理内心形始终为 toggle；在收藏集内整理再点 = 取消收藏；结算「本次收藏」只计净新增，不为负。  
5. 零收藏仍保留入口，显示轻量空态 sheet；有收藏时复用已有浏览器。
6. ASCII 定标题栏有收藏与零收藏两种状态；封面 / 紧凑 / 列表都共用这组标题栏入口。
