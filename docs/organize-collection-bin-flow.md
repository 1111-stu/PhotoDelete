# 整理收集箱与本轮结算：交互决策与 ASCII 原型

决策日期：2026-10-11。  
状态：**产品定稿，已落地代码（2026-10-11）；待真机回归。**。  
范围：整理页（`SwipePhotoView`）退出/完成、全局待删除收集箱、本轮结算弹窗；不含系统「最近删除」清空引导（见 `recently-deleted-empty-research.md`）。

---

## 1. 一句话定稿

**一个全局收集箱；退出不拦截；真删只在收集箱；点完成或本轮到头再往外滑 → 同一张本轮结算弹窗（单按钮「完成」离开）。**

---

## 2. 核心原则

| # | 原则 | 说明 |
| --- | --- | --- |
| P1 | 全局收集箱 | 所有「划上待删」进同一份 `deleteCandidates`；本轮 / 上轮 / 首页右上 / 整理右上，看的都是这一份 |
| P2 | 退出不拦截 | 左上返回直接离开；不弹确认、不提交删除 |
| P3 | 完成 = 结算 | 右下「完成」先出本轮结算弹窗，再离开；**不等于**提交删除 |
| P4 | 真删唯一入口 | 仅收集箱内「删除所选 → BatchConfirm」会触达系统删除 / Recently Deleted |
| P5 | 本轮 ≠ 全局 | 结算弹窗同时展示「本次」指标与「收集箱共计」，避免用户以为箱里只有本轮那几张 |
| P6 | 不做双箱 | 不做「本轮删除箱 + 全局删除箱」并列产品；也不做「再来一轮」作为结算主路径 |

---

## 3. 交互决策表

| 入口 | 行为 | 不做什么 |
| --- | --- | --- |
| 上滑 | 标进全局收集箱（角标累加） | 不立刻删系统照片 |
| 左右滑 | 浏览翻页 | 不记「保留」、不弹结算（除非越界，见下） |
| 整理页右上 `archivebox` | 打开收集箱（与首页同一数据） | 不是离开本轮 |
| 首页右上 `archivebox` | 打开同一收集箱 | — |
| 左上返回 | **直接 dismiss** | 不拦截、不出结算、不确认删 |
| 右下完成 | **出本轮结算弹窗** | 不进 BatchConfirm |
| 本轮最后一张再往「下一张」滑 | **出同一张结算弹窗** | 不只橡皮筋弹回 |
| 仅停在最后一张 | 不自动弹 | 等再往外滑或点完成 |
| 结算弹窗「完成」 | 关闭弹窗并离开整理页 | 不确认删、不再来一轮 |
| 收集箱内删除 | 选中 → 确认 → PhotoKit 删除 | — |

### 3.1 与旧逻辑的差异（实现时必须改掉）

| 旧行为 | 新行为 |
| --- | --- |
| 返回 / 完成：有待处理 → `BatchConfirm` | 返回直接走；完成 → 结算弹窗 |
| 结算主按钮「确认删除」 | 单按钮「完成」离开 |
| 随机完成副文案「确认后再删除」 | 去掉确认话术 |
| 最后一张再滑 → 橡皮筋 | → 触发结算弹窗 |
| 整理右上 `trash`、完成钮 `archivebox` | 右上改 `archivebox`；完成改 `checkmark`（或同等「离开/勾」语义） |

## 4. 图标语义

| 位置 | 图标 | 语义 |
| --- | --- | --- |
| 首页右上 | `archivebox` | 全局收集箱（已有） |
| 整理页右上 | `archivebox`（替换原 `trash`） | 同一收集箱；可挂全局数量角标 |
| 整理页右下完成 | `checkmark`（替换原 `archivebox`） | 结束本轮 → 结算 |

箱子 = 收集；勾 = 结束本轮。二者不再共用 `archivebox`。

---

## 5. 本轮结算弹窗：何时出现

同一套 UI，两个触发源：

1. **主动完成**：点右下完成钮  
2. **自然到站**：已在本轮最后一张，再向「下一张」方向滑（越界）

左上返回 **不** 触发。

适用：随机批次（如 20/50/…）及其他有限队列整理；非随机「通道已空」可复用同一卡片骨架，顶栏文案按通道名切换（见 §7）。

---

## 6. 结算弹窗：信息结构（定稿）

### 6.1 展示项

| 行 | 文案方向 | 数据（本轮 / 全局） | 是否支持 |
| --- | --- | --- | --- |
| 顶栏左 | 通道名（如「随机整理」「整理今天」） | 当前整理来源标题 | 有 |
| 顶栏右 | `N 项` | 本轮队列规模或本轮已浏览进度（实现时与 header 进度对齐） | 有 |
| 行 1 | 本次待删除 | `PhotoReviewActions.deleteActionCount` | **有（本轮）** |
| 行 2 | 本次收藏 | `PhotoReviewActions.favoriteActionCount` | **有（本轮）** |
| 行 3 | 收集箱共计 | `DataManager.deleteCandidates.count` | **有（全局）** |
| 底栏 | 唯一主按钮「完成」 | dismiss 整理页 | — |

**不展示「本次保留」**：当前没有「保留」手势/记录；左右滑仅为浏览。硬算「看过 − 待删」会误导。若未来产品补「保留并记已整理」，再加第四行。

**不做「再来一轮」**：减法；要再整理从首页/入口重新进。

### 6.2 ASCII 原型（结算弹窗）

```
┌──────────────────────────────────────┐
│  ████████  整理幕布（半透明遮罩）        │
│                                      │
│     ┌────────────────────────┐       │
│     │ 随机整理          20 项 │       │
│     │                        │       │
│     │ ● 本次待删除         3 │       │
│     │ ● 本次收藏           1 │       │
│     │ ● 收集箱共计        11 │       │
│     │                        │       │
│     │  ┌──────────────────┐  │       │
│     │  │      完成         │  │       │
│     │  └──────────────────┘  │       │
│     └────────────────────────┘       │
│                                      │
└──────────────────────────────────────┘
```

视觉参考（竞品气质，非像素还原）：顶栏次级字 + 大号数字行 + 单条深色胶囊主按钮；色点区分行语义（待删偏珊瑚/危险，收藏偏爱心色，收集箱用中性或琥珀强调「全局库存」——实现时跟 `Theme`）。

### 6.3 文案约束

- 「本次*」只用于本轮两行；第三行必须出现「收集箱」或「共计」字样，禁止再写「本次」。  
- 可以为 0；结构固定三行，不因 0 隐藏（避免布局跳动）。  
- 第三行 **不是** 按钮；清箱仍走 `archivebox`。

## 7. 整理页 Chrome：ASCII

```
┌──────────────────────────────────────┐
│  [←]         8 / 20        [箱 11]   │  ← 返回直接走；右上 archivebox + 全局角标
│                                      │
│           ┌────────────┐             │
│           │            │             │
│           │  照片卡片   │             │
│           │            │             │
│           └────────────┘             │
│           日期 · 地点 …              │
│                                      │
│  ( 详情  撤销  心  分享 )    ( ✓ )   │  ← 右下完成 = checkmark → 结算弹窗
└──────────────────────────────────────┘

手势：
  ← / →  浏览
  ↑      进收集箱（待删）
  最后一张再 →  结算弹窗
```

收集箱页（整理内 / 首页入口同一数据，CTA 可分场景）：

```
┌──────────────────────────────────────┐
│  收集箱 / 待删除                      │
│  ┌──┐ ┌──┐ ┌──┐                     │
│  │  │ │  │ │  │  …                  │
│  └──┘ └──┘ └──┘                     │
│                                      │
│  [移出所选]        [删除所选]         │  ← 真删只在这里（及确认页）
└──────────────────────────────────────┘
```

说明：整理会话内打开的队列页，主按钮可为「继续整理」（关 sheet 回到卡片）；首页进入的主按钮为「删除所选」。**数据源相同**，仅主 CTA 不同。

## 8. 端到端流程

```
首页
  ├─ archivebox → 收集箱 →（可选）删除所选 → BatchConfirm → 系统删除
  │
  └─ 进入整理（随机 20 / 通道 / 相册…）
        │
        ├─ ↑ 待删 ──→ 写入全局 deleteCandidates
        ├─ 心 收藏 ──→ 立即生效（本轮计数进结算「本次收藏」）
        ├─ ← → 浏览
        │
        ├─ [←] 返回 ──────────────→ 直接离开（箱保留）
        │
        ├─ [✓] 完成 ──┐
        │             ├──→ 结算弹窗（本次待删 / 本次收藏 / 收集箱共计）
        └─ 末张再滑 ──┘         │
                                └─ [完成] → 离开整理页
```

心智口令：**先标、后清、随时走；结算只汇报，不结账。**

## 12. 决策日志（对话收敛）

1. 先讨论全局箱 vs 按轮箱 → 定 **全局收集箱**，退出不拦截。  
2. 右上收集 vs 右下完成职责冲突 → 完成只离开/结算，真删只在箱。  
3. 返回与完成均曾定为「直接走」→ 补充：**完成出结算，返回静默走**（完成钮才有独立意义）。  
4. 随机完成曾议「再来一轮 + 返回主页」→ 改为竞品式 **单按钮结算**，去掉再来一轮。  
5. 调研三指标 → **本次待删除 + 本次收藏**；不做本次保留；再补 **收集箱共计**。  
6. 末张再滑应触发结算（相对现状橡皮筋）。  
7. 图标：右上与首页统一 `archivebox`；完成不用箱子。
